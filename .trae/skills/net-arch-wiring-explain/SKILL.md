# Net Arch Wiring Explain

用户问「这个分支装到骨干哪里」「融合发生在哪」时，用本流程回答。
目标产出必须满足两条：**一眼就能看懂它在做什么**，且**读者能指出代码的某一行**。

## 硬性规则

1. **第一句必须是人话。** 不许以「跨注意力」「早融合」「特征级融合」开头。用「一个什么模块，对什么特征，做了什么事」的句式。
2. 先读代码，再回答。禁止凭类名、docstring、论文描述推断结构。
3. 每个结构断言都要能落到一个 `file:///...#Lx-Ly` 行号区间。
4. 禁止用图示工具（`PureShowWidget` 等）。连线图用代码块画 ASCII。
5. 若代码与文档/注释不一致，以代码为准，并显式指出不一致处。
6. 改完代码后必须跑一次 `python -m py_compile <file>` 验证。

## 步骤

### 0. 先用一句人话定性（最重要）

开头第一段，不加任何限定词，直接说清楚三件事：**谁**（什么模块）、**对谁**（哪一层的什么特征）、**干了什么**（加权 / 相加 / 替换）。

模板：

> 通过一个 **<特征提取模块>**，把 **<骨干>** 的 **<哪一层>** 特征**<加权 / 相加>**。

本项目示范（照抄这个语感）：

> 通过一个 4 层卷积的小特征提取模块，把 TransUNet **编码器的输出特征**做加权。

紧接着第二句必须给**力度判定**，因为这才是听的人真正关心的：

> 但融合比较少：只在 **<一处>** 做，且作用在 **<分辨率>** 上，不是真正的多路深度特征融合。

判定「融合力度」用下面这张表，逐项打勾，缺一项就是「少」：

| 维度 | 力度强 | 力度弱 |
|---|---|---|
| 路数 | 两套独立权重 | 一套权重 + 一个小模块 |
| 层级 | 浅/中/深多层都做 | 只在最后一层做一次 |
| 分辨率 | 保持 1/4、1/8 细节 | 只在最粗的 1/16 |
| 输入来源 | 完整图像 / 另一模态 | 主分支输入的某个通道 |
| 交互方向 | 双向、用对方的权重 | 单向、只取对方特征 |

只要「层级」和「输入来源」两列落在弱侧，就可以直接说「融合不足以支撑增益」。

### 1. 定位被插入的位置

找到基类的 `forward`，找出被子类**打断**的那条箭头。典型形态：


```python
x, aux, feats = self.encoder(x)   # 骨干出口
x = self.decoder(x, feats)        # 解码器入口
# ↑ 插入点就在这两行之间
```

回答时先写出基类这两行 + 行号，再说明子类插了什么。

### 2. 画模块树

列出最外层的 `self.*`，把新增模块用 `★` 标出，并注明它们挂在**哪一层**
（最外层 / encoder 内部 / decoder 内部）。这一步用于证明「它没有伸进骨干内部」。

```
VisionTransformer
├── self.transformer        ← 骨干本体
│   ├── embeddings (stem + patch_embed)
│   └── encoder (12 × Block)
├── ★ self.wave_branch
├── ★ self.wga
├── self.decoder
└── self.segmentation_head
```

### 3. 固定回答五个问题

这五问是产出核心，缺一不可：

| 问题 | 必须给什么 |
|---|---|
| 挂在骨干哪一层？ | 具体到「第几个 Block 之后 / 第几个 stage 输出」 |
| 输入从哪里取？ | 被插入位置的自身特征？模型原始输入？另一层的中间特征？ |
| 输出注入到哪？ | 相加 / 拼接 / 替换，注入哪一层的哪个张量 |
| 绕过了什么？ | skip 连接、多尺度特征、辅助头是否受影响 |
| 一共有几个接点？ | 明确数量；只有一个就说只有一个 |

### 4. 给张量走查

逐层写形状变化，格式统一为 `(B, C, H, W)` 或 `(B, N, D)`。
嵌入公式时给维度数值（如 4 头 → 每头 192 维）。

### 5. 给一个已知结构的类比

用「相当于在 XXX 的 stage4 后加 SE」这类句式，把新结构锚到读者熟悉的东西上。
重点说明**差异只在哪**（例如：SE 的 Q/K/V 都来自自身，这里 K/V 来自外部）。

### 6. 收尾给结构后果

一句话说明这个接法**天然能拿到什么、拿不到什么**。
这是解释「为什么指标没涨」的依据，不是猜测。

## 反面写法（禁止）

- **开头就甩术语**：「采用跨注意力进行特征级融合」——听的人不知道在做什么。
- 「在特征层做了融合」——没说是哪一层、哪一维。
- 「双分支结构」——先确认是否真有两套权重，再下这个结论。
- 「侧支融合了细节信息」——若侧支输入是主分支输入通道的子集，必须点明冗余。
- 只画一个漂亮的框图，不给行号。
- 把「机制细节」放在「一句话定性」之前。顺序永远是人话 → 位置 → 形状 → 后果。

## 交付检查

回答前自检：

- [ ] 第一段能让人不看代码就说出「它在对什么做加权」
- [ ] 第二段给出了融合力度判定，并说明为什么算「少」
- [ ] 每个「在哪」都对应一个可点击的行号链接
- [ ] 五个问题全部回答，没有跳过「绕过了什么」
- [ ] 张量形状前后自洽（通道数、token 数能对上）
- [ ] 没有使用图示工具
- [ ] 若动过代码，`py_compile` 已通过
