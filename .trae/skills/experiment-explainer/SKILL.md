# 实验讲解（experiment-explainer）

目的：人不能落后于 agent 的思路。每个实验、每个模型改动，都必须有一份人能独立读懂的讲解文档；结果一出就更新文档，再向用户汇报。

## 触发时机

1. 用户要求讲解/解释某个实验、模型、指标、结果（"这是什么意思""我没看懂""请讲解"）。
2. agent 跑完一个新实验或做了模型/数据改动，产生了新结论。此时**主动**把新结果写进对应讲解文档，不允许只在对话里口头汇报。
3. 同一主题已有讲解文档时，**更新该文档**，不另起炉灶、不重复内容。

## 输出位置与命名

- 目录：`docs/study/`
- 文件名：kebab-case 英文，如 `tinycnn-explained.md`、`edge-fusion-explained.md`
- 单篇控制在 200 行以内；超了就拆分主题或压缩。

## 固定模板（每篇必须齐全）

```markdown
# 标题：一句话说清这篇讲什么

配套代码：文件链接；概念背景：相关 study 文档链接。

## 0. 一页版
一句话结论 + 最重要的数字/表格。只读这一节也能明白发生了什么。

## 1. 输入是怎么处理的
从原始数据到网络输入，每一步写清「运算 → 输出是什么 → 代码行号」。
凡是有别名的东西必须显式消歧，例如：
「小波高频图」「边缘图」「HF 图」在本项目里指同一样东西——
对数域 1 级 Haar DWT、LL 置零、IDWT 重建、expm1 回原域、逐样本 z-score。
禁止只说"边缘图"而不给定义。

## 2. 模型与损失
- 逐层表：层名 | 运算（含 stride/通道数）| 输出尺寸 | 作用；
- 参数量与对照基线的比值；
- **特征融合模块（必写，这是最常被追问的部分）**，逐项讲清：
  - 融合位置：接在哪一级、什么分辨率、两条支路各多少通道；
  - 融合轴向：低频/高频/原图信息**各走哪条路**（通道轴=同位置拼接回投影；
    空间轴=QKV 跨位置注意力；两者必须显式区分，不许混称"融合"）；
  - 算子公式：一行数学式写死，如 `A' = A + γ·Conv1x1(cat(A,B))` 或
    `A' = A + γ·Proj(Attn(Q=A, K=V=B))`；
  - 初始化与残差：γ 是否零初始化、归一化放在支路内还是外、
    为什么不能出现两个零因子相乘；
  - 参数增量：相对基线多了多少参数，值不值；
  - 对照档位：本方案与哪些融合算子（gate/concat/attn/deform）摆过对照，
    差值各自归因于什么；若结论是"该轴不适用"，必须给出判别性对照的证据
    （如侧路喂全零仍涨 → 涨幅不来自内容信息）。
- 损失函数：写出具体形式（如 F.cross_entropy 对 2 通道 logits），
  有没有权重、辅助损失、深监督；
- 训练配置：优化器/lr/调度/batch/epoch/seed/增强，并说明**为什么这么选**。

## 3. 指标与结果
- 每个指标一句大白话定义 + 它会被什么假象影响（如阈值漂移）；
- 结果表：绝对值 + 相对差值，差值必须说明归因于哪个变量；
- 「怎么读」：指出哪几条是证据、哪几条是噪声。

## 4. 代码实现在哪里
文件 + 行号链接（file:/// 绝对路径 #L 形式），入口脚本、核心类、
数据构造、评估各一条。读者要能按链接直接跳到可运行代码。

## 5. 结论边界与其他
- 能说 / 不能说 对照表；
- 已知局限（seed、天花板、欠训练、子集差异等）；
- 复现命令（PowerShell 完整命令，含 venv 路径）；
- 与其他方案的对比（若本文档涉及取舍，如通道轴 vs 注意力轴）。
```

## 写作规则

1. **大白话优先**：术语第一次出现必须当场用一句话解释；缩写先给中文全称。
2. **只用已跑出的数据**：讲解文档里不许出现没跑过的数字；需要新实验才能下结论时，先在文档里写明"待验证"，不许为了补文档去跑长实验让用户干等。
3. **对照实验讲清控制变量**：写明白"哪两个变体之间只差 X，所以差值可归因于 X"。
4. **不堆术语表**：附录名词解释控制在必要范围内，能用类比就不用公式。
5. 更新文档时保留原结构，只增改受影响的小节；过期数字直接改正并注明出处实验，不留"旧结果"段落。

## 反例（禁止）

- 只把终端输出表格贴进文档，没有"怎么读"；
- 说"输入是边缘图"却不定义边缘图是什么运算；
- 讲解文档与 status.md 内容重复——status.md 只放状态一句话 + 指向 study 文档的链接；
- 用户问"这是什么意思"，只在聊天里回答而不落文档。
